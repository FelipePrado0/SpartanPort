# Spec: build de diagnóstico `Tex:` (SPARTAN_TEX_TRACE)

Frente: corrupção progressiva de texturas. Branch `diag/texture-corruption`.

## SDD

* **Objetivo:** como mantenedor, quero que o `last_run.log` registre o que o cache de texturas fez com a memória do jogo (descartes, downloads, writebacks, cancelamentos, unmaps, troca de autoridade de alias) e um resumo por intervalo, para correlacionar o primeiro artefato com a operação exata, sem afetar quem não liga o diagnóstico.
* **Contrato:**
  * Variável `SPARTAN_TEX_TRACE`: só o valor exato `1` liga; ausente ou qualquer outro valor desliga. Lida uma vez por processo.
  * Desligado: nenhuma alocação (o `TexTrace` é `nullptr`), cada gancho é um teste de ponteiro nulo; nenhuma linha `Tex:`.
  * Ligado: a cada 5 s (no `RunGarbageCollector`), uma linha `Tex: summary <s>s created=N (MiB) destroyed=N (MiB) evict=N (MiB) download=N (MiB) writeback=N (MiB) cancel=N unmap=N alias-forget=N gc=N runs <ms> ms max <ms> ms cache=<MiB> trigger/pressure/critical=<MiB>/<MiB>/<MiB> MiB`; uma linha `Tex: heap <i> [device-local] size <MiB>, usage <MiB>, budget <MiB>` por heap (quando o driver informa VK_EXT_memory_budget); e até 64 eventos mais novos do intervalo, um por linha: `Tex: <evict|download|writeback|cancel|unmap|alias-forget> addr=<guest> size=<bytes> img=<slot> uid=<uid> fmt=<VkFormat> pitch=<px> extent=WxHxD flags=<ImageFlagBits> writer=<slot>/<uid> backing=<slot>/<uid> reason=<motivo> tick=<GPU tick> gc=<gc tick> mapgen=<unmaps vistos>`. Eventos não impressos: `Tex: N older events not printed`.
  * Motivos: `gc-trigger`/`gc-pressure`/`gc-critical` (evict/download), `deferred`/`frame`/`queue-full` (writeback), `unmap`/`delete` (cancel), `guest` (unmap), `delete` (alias-forget).
* **Critérios de aceite:**
  * QUANDO `SPARTAN_TEX_TRACE` não for exatamente `1`, O SISTEMA DEVE ficar desligado e não imprimir linhas `Tex:`.
  * QUANDO ligado e houver mais eventos que a capacidade (4096) ou que o limite por relatório (64), O SISTEMA DEVE manter só os mais novos e informar quantos não imprimiu.
  * QUANDO ligado, O SISTEMA DEVE imprimir o resumo do intervalo e zerar os totais a cada relatório.
  * QUANDO uma linha não couber no buffer, O SISTEMA DEVE truncá-la sem escrever fora dele.
* **Requisitos não funcionais:** desligado, custo de um teste de ponteiro por gancho; ligado, um mutex por evento e ~400 KB de ring; sem conteúdo de texturas nem dados pessoais no log (só endereços, tamanhos, formatos e contadores); sem alterar o comportamento do renderer.
* **Arquivos afetados:** `gpu/shadps4/video_core/texture_cache/tex_trace.h` (novo), `texture_cache.h`, `texture_cache.cpp`, `tests/test_tex_trace.cpp` (novo), `gpu/CMakeLists.txt` (alvo `tex-trace-test`).
* **Plano técnico:** lógica pura (evento, ring, formatação, totais, leitura da variável) num header testável sem Vulkan; ganchos no cache: `RegisterImage` (criada), `DeleteImage` (destruída, alias-forget quando a imagem era writer/backing), GC (`download`/`evict` com o nível do GC), `RetireReadbacks`/`ProcessDownloadImages` (writeback), `CancelReadbacks` (cancel), `UnmapMemory` (unmap e contador local `mapgen`, pois não existe geração de mapeamento exportada pelo runtime; dependência registrada para a frente de memória), tempo do GC após o limiar de disparo. Riscos: o resumo usa o uso de memória do cache (`total_used_memory`, que com VK_EXT_memory_budget é o uso de todo o dispositivo); writebacks por frame podem dominar o ring (por isso o resumo conta todos e só os 64 mais novos são impressos).
* **Validação:** `tex-trace-test` (desligado por padrão, formatação, truncamento, ring, resumo e reset), compilação do objeto `texture_cache.cpp`; no jogo, roteiro do mantenedor.
* **Aprovação:** aprovada pelo líder por delegação do mantenedor (29/10/2026).
